# 磁盘空间助手

一个面向 Windows 的原生 WPF 磁盘清理与空间分析工具。程序先扫描并展示候选文件，只有用户明确选择和确认后才会执行清理；发布版本是无需另外安装 .NET 的 64 位单文件 EXE。

## 新版工作台与界面升级（v3.0.0）

- 深蓝导航侧栏、靛紫主操作、青绿容量状态和珊瑚红危险操作，统一圆角输入框、按钮、表格、选中态及风险色标。11个页面沿用原有扫描与回收流程，不因换肤放开保护规则。
- 新增“磁盘概览”：本地固定磁盘的总容量、已用、可用空间与使用率环图；80%/90%容量提示。容量数据来自卷计数器，不是目录分类结果，也不代表磁盘健康诊断。
- 点击磁盘“分析”或常用目录“分析”后，才会开始该路径的空间分析。常用目录最多收藏12个，本地保存、可右键操作与导出，不自动扫描或清理；此明确指定路径的分析不套用全局范围白名单，但仍遵守永久排除与原件保护。
- 首页提供空间树、NPS完整工程、开发环境、重复文件、媒体、软件占用与快速清理入口；“1 GB以上文件视图”只切换空间页并设置大小阈值，不冒充已经完成扫描。快速清理候选合计只统计已有扫描结果，未扫描明确显示，不是保证可释放空间。
- 启动不再自动枚举文件，只异步读取本地固定盘容量；不主动查询网络盘、可移动盘或加载媒体内容。磁盘环图为原生轻量绘制，表格保留行/列虚拟化，不为每行增加阴影或动画。
- 普通表格的复选框列支持单击勾选与取消，禁用项、只读列和业务层保护继续生效；NPS页面保留原有直接勾选与整工程回收方式。统一右键菜单覆盖11页、23个对象区域。
- 扫描范围设置折叠为顶栏入口，启用时显示范围数量；旧偏好、索引和审计保留。首次使用3.0打开概览，之后记住最后页面。

最新单文件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)。只分享这个EXE，无需另装.NET；每个使用者的数据仍保存在其自己的本地应用数据目录。界面预览使用明确标注的示例容量，不是本机扫描报告。验证记录见 [v3.0验证记录](RELEASE-3.0-VERIFICATION.md)。

## NPS-EMT 完整工程综合识别（v2.8.0）

清理单位改为完整工程文件夹，不再把孤立npsdata当作主要删除对象。主列表一个工程一行，自动统计整个目录大小，勾选后只需一次确认即可整目录移入回收站，包含模型、脚本、仿真结果、编译产物、工程内备份等全部内容。

- 工程发现不再要求存在npsdata：有效`.emtproj`的XML结构与`model`目录（或至少两种配套目录）可共同确认工程。模型数据库缺失/尚未创建也能识别；一个下载来的清单、但没有工程布局，不会授权回收整个共享文件夹。
- 缺少工程清单时，结合`model`以及至少两种`script/result/external/loadflow/fpga_bin/monitor`配套目录，再由已支持的模型数据库结构或NPS专用脚本标记相互印证。没有清单、没有npsdata但保留标准结构和NPS脚本的目录也能列为综合识别工程。
- 文件后缀、目录名、备份名称、普通SQLite库都不能单独作为整目录删除依据。普通布局但没有NPS专用证据的目录列为待核实候选；孤立模型只作待归属线索，不单独删除，不把微信/下载整个父目录当工程。
- 多个模型按最近的工程根目录归并，只显示一个工程总大小。默认只显示已识别的完整工程，候选、孤立线索与恢复快照可切换查看；右键详情/CSV包含综合识别依据。
- 回收前重新检查识别依据、工程边界和快照。清单缺失不代表无条件放开删除；目录内有另一个独立清单工程或综合结构工程时阻止父目录整体回收。原有系统/安装/整个用户根、原件/排除、Git、链接/云占位、工具恢复快照保护保留。
- 保留自动大小降序、直接单击勾选、全选、无每批100项限制、一次确认、全局模拟和逐项记录。回收站未清空前实际释放为0。识别为本地规则与有限内容核对，不保证覆盖所有NPS版本或任意导出格式；识别不充分时只列候选。

最新单文件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)。测试与发布信息见 [v2.8验证记录](RELEASE-2.8-VERIFICATION.md)。下面v2.7的单文件删除流程已被本版替换。

## 历史功能：NPS-EMT 工程清理（v2.7.0）

第10页“NPS 工程”现在只需：**扫描 → 看大小 → 勾选 → 删除到回收站**。只有一张列表，左侧复选框可直接单击；删除前只弹一次确认，不需要手动测量或输入确认文字。

- 默认搜索全部就绪的本地固定磁盘，**不受其他页面的白名单限制**；指定目录模式才优先使用下方白名单，否则使用页面目录输入。可额外发现可移动盘，但整目录回收仅允许本地固定卷。文件名无论藏在多深的普通/隐藏目录都按枚举范围检查；链接、离线/云占位、系统回收/卷管理目录、无权限位置和深度超过512的路径会记录跳过，不能承诺不可访问区域也不遗漏。
- 依据提供的本机样例核对 `.emtproj` 的 XML Project/Version/配置结构，禁用DTD及外部解析，清单最多1MiB；检查 `.npsdata` 的SQLite签名和model/block表。数据库有WAL/SHM/恢复日志时只列候选，不打开数据库，以免生成或改写辅助文件。格式未知/受损标志仍保留为提示，不直接丢弃。
- 区分工程、备份（路径名称推断）、工具恢复快照、独立/未归属模型和疑似工程。恢复快照默认从主列表隐藏，可通过分类查看全部；搜索、右键、位置/详情/排除、CSV、设置、发现记录重开均已接入。模型文件标志数不等于内部画板数；不依据文件名/年龄或相同工程清单判定工程无用、重复或已经备份。
- 发现阶段只保留匹配标志，不对全盘每个文件做实际占用读取；匹配索引和最近清单写SQLite。可访问范围遍历、最多2路SSD多范围并行，HDD/未知顺序，有界256条写入队列，取消保留部分清单。标志上限100,000、工程/独立模型结果上限20,000；达到上限明确标部分，不把百万普通文件路径全部放进发现结果内存。尚不是NPS专用USN增量引擎。
- 扫描后自动统计所有发现项的逻辑大小、实际占用、文件数，默认按大小从大到小排列。可“全选当前列表”或取消全部勾选；筛选不会丢掉其他已勾选项，删除确认明确总项数、大小、目录/文件数量。取消统计保留部分大小，未读取项不会冒充完整大小或允许删除。
- 已取消每批100项测量/回收限制，NPS勾选/删除也不受通用右键菜单1000行限制；SQLite保存逐文件快照，目录遍历只保留每层一个枚举器，批量选择一次更新汇总。发现标志100,000/结果20,000和512目录深度的资源保护仍保留，达到限制明确提示部分结果。
- 独立 `.npsdata` 显示文件真实大小，支持勾选回收**该文件本身**，绝不删除其父目录。未知格式标明“格式未验证”，由用户决定是否删除文件；数据库有WAL/SHM/journal、系统/排除/原件保护、链接、云占位或工具恢复路径仍禁止回收。个人模型文件位于软件数据目录时不再套用“整个安装目录”的禁止规则。
- 整个工程目录仍需本层有效清单、model和至少两个配套目录；系统/安装/卷根/整个用户目录、原件/排除、链接/云占位、不完整、包含其他工程、Git工作树和工具恢复快照不可整体回收，但仍显示统计大小，并在同一行说明原因。
- 回收前自动核对清单、结构、文件身份/大小/时间/硬链接与当前保护规则；内容变化请重新扫描。检测NPS或工程内程序运行时跳过，不强制结束。确认时提醒备份和关闭NPS，不替用户建立或验证备份。保留全局“模拟清理”设置，开启时不会真实删除。
- 先持久记录执行意图，再强制进入Windows回收站，失败不会永久删除。记录逐项结果和失败原因；回收站未清空前实际释放为0。

样例目录 `D:\AAA_work\model\SimuNPS-EMT`：发现141项（17普通、4备份、120恢复快照），查看9,045个文件、跳过0；所有141项自动得到完整大小，21个普通/备份工程可勾选。此轮只读“发现＋大小统计”约3.3秒，普通/备份工程逻辑大小合计143,234,163字节。NPS占用读取只申请文件属性访问，不打开文件内容；实測是这个样例，不代表全盘耗时，且两轮文件系统缓存不同。没有回收用户工程。

本地数据为 `%LOCALAPPDATA%\DiskCleanupAssistant\nps-projects.sqlite`（标志、大小、最近清单、回收审计）和 `nps-measurements.sqlite`（文件快照），含个人路径信息。“打开上次结果”自动更新大小与可删除资格，不再要求手动测量。最新软件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)，只分享这个EXE。验证与发布哈希见 [v2.7验证记录](RELEASE-2.7-VERIFICATION.md)。

## 全页统一右键菜单（v2.5.0）

九个页面都有右键菜单，包含结果行、页面空白处及操作记录/原件保护/排除列表。不是把空间页的“删除目录”菜单硬套到其他页面；根据文件、目录、软件、记录和保护状态提供相应动作。

- 常用项保持一致：打开当前项位置（文件在资源管理器定位，目录直接打开）、系统属性、复制所选路径/名称/详细信息、只读扫描详情、永久排除、刷新和CSV导出。注册表、Docker命令详情和历史记录不能当本地文件打开；输入框仍保留原生文字编辑菜单。
- 右键未选中的行会选中该行；右键已有多选中的行保留多选，但菜单明确显示实际指向项。打开位置/属性针对当前指向项，批量复制和勾选针对高亮所选行。“高亮所选行”与“清理/卸载勾选计划”是两种状态，执行入口明确写“已勾选”，仍包含之前勾选的项。
- 空白处只显示页面级操作，不复用上一次右键行的路径。菜单键或Shift+F10打开当前所选项菜单，Ctrl+C复制所选路径/记录；菜单打开后也可Ctrl+C。不会自动打开/执行文件；没有快捷Delete绕过确认。
- 重复中心：勾选/取消所选副本，指定保留当前副本并勾选同组其他副本，所在目录设原件保护，回收/硬链接进入原有安全流程。组内至少保留一份，原件/排除项不进入计划；记录可定位保留或异常恢复文件。
- 相似媒体：查看组内对比、仅查看当前相似组/恢复全部组、原件保护及排除，不新增媒体删除。开发环境：按资格勾选、模拟、可重建回收、Git工作树移除、归档成果人工确认；软件页：按资格勾选、模拟、还原点前置卸载和Windows设置。历史/残留记录仍只读，WSL虚拟盘没有直接删除入口。
- 危险操作沿用原有确认、实时保护、重哈希/Git/任务归属检查、还原点和模拟模式；忙碌、过期、历史快照、受保护或未知项目不能借菜单绕过。禁用动作变淡并可查看说明。
- 打开菜单只查看选中对象，不遍历ItemsSource、读取文件内容或计算哈希。批量菜单最多1000个高亮行，超过上限禁止批量修改/复制但保留CSV导出；详情窗口预览前20项，复制上限1MiB。批量排除一次保存，并以临时文件落盘后同目录替换，失败回滚内存状态，避免每行重复写入。

最新单文件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)。只需分享这个EXE。测试与发布记录见 [v2.5验证记录](RELEASE-2.5-VERIFICATION.md)。

## 软件占用与卸载残留（v2.4.0）

新增第9页“软件占用”。默认只扫描与提示，所有项目默认不选；不自动卸载，不删除疑似目录/注册表残留。最新单文件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)。只分享这一个 Windows x64 EXE，无需另装 .NET；新页面不依赖或捆绑 BCUninstaller。

- 桌面软件：只读 HKLM/HKCU 的32/64位卸载登记，显示名称、发布者、版本、安装路径、卸载入口及系统登记大小，并按占用排序。不使用可能触发 MSI 自动修复的 Win32_Product。位置未知、缺少入口或指令不支持均明确提示，不把便携/共享目录认定为垃圾。
- Windows Store：读取**当前用户**的应用包，框架、资源包和 NonRemovable 项禁止批量卸载；不改其他用户，不手工删除 WindowsApps。包没有报告大小时显示未知，不能用0冒充真实占用。
- 游戏：读取 Steam 多库清单、游戏安装位置及平台报告大小；Epic 常见默认清单也纳入分析。Steam 卸载交给客户端并停止后续队列，等待你在平台确认后重扫；Epic 仅分析，不直接卸载。不宣称完整覆盖所有游戏平台或 Windows 可选功能。
- 快速清单默认不遍历大型安装目录。“实际测量安装目录”可统计逻辑大小、磁盘实际分配和文件数，遵守白名单、参考/排除规则，跳过链接、离线/云占位和恢复文件，读取不全明确标部分。最多1,000,000个条目，单目录最多250,000个物理身份。安装路径重叠、共享框架与跨软件硬链接不能相加；登记大小和平台大小只是报告值，不是实测释放量。
- 孤立与残留：常见 Program Files 顶层目录没有匹配软件登记时，只标“未登记/便携/共享”；软件登记在**两次完整来源扫描**中消失后，才按确切归一名称关联 AppData、ProgramData 的顶层目录及 HKCU/HKLM Software 顶层注册表项。共享厂商名排除，来源缺失/读取失败不会累计消失次数。首次使用没有历史依据，不能证明以前遗留的 AppData 无用；更名、重装、共享组件和个人存档都可能误判。发现不是穷尽扫描，永远只有只读提示，没有残留删除入口。
- 手动勾选软件后可先“模拟卸载检查”，不启动卸载程序、不建立还原点。真实批量卸载需要再次确认；先请求 UAC 并验证**本批新建的系统还原点**，失败、系统保护关闭、权限不足、不同账户提权或系统频率限制时停止，不更改系统保护策略、不用旧还原点冒充新建。Windows 客户端通常限制24小时内创建一个还原点；还原点不是配置/游戏存档/个人文件备份。
- 实际卸载逐个运行厂商/Windows 的交互入口，MSI 使用产品编号构造命令；不添加静默参数。命令身份、软件版本和保护规则会在执行前重新验证；不执行 cmd/PowerShell/rundll32 等任意脚本宿主登记字符串。退出后还要核对登记是否消失；取消、失败、登记仍在或平台接管时停止队列。取消等待不会强杀卸载程序。已登记但入口不支持的项，可跳转“Windows 已安装应用”处理。
- 逐项执行意图、还原点、返回码、登记核对结果和失败原因持久记录。不会把登记消失或理论大小冒充实际释放空间。支持分类筛选、全局搜索、占用排序、打开位置、复制路径、CSV导出、设置保存和虚拟化表格。

安装历史与卸载审计保存在使用者自己的 `%LOCALAPPDATA%\DiskCleanupAssistant\software-inventory.sqlite`，包含本机软件名称、路径、版本和卸载登记，属于个人信息，不应随意分享。UAC还原点请求/回执在同目录的 `software-actions\restore` 下。仅启动程序或打包诊断不会自动扫描、卸载或创建还原点。验证说明见 [v2.4验证记录](RELEASE-2.4-VERIFICATION.md)。

功能组织参考 [BCUninstaller](https://github.com/BCUninstaller/Bulk-Crap-Uninstaller)，独立实现，没有复制/捆绑其代码。系统接口依据 [卸载登记说明](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)、[商店应用查询](https://learn.microsoft.com/en-us/powershell/module/appx/get-appxpackage?view=windowsserver2025-ps)、[还原点创建条件](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/checkpoint-computer?view=powershell-5.1)。

## 开发环境清理中心（v2.3.0）

新增“开发环境”页：选择项目或项目集合目录，分析项目、Git 工作树、构建输出、Codex 产物和包缓存。项目扫描遵守下方白名单；Codex 目录、用户级缓存和 Docker 分别独立勾选，用户级缓存默认不扫描。所有清理项默认不勾选，支持分类筛选、全局搜索、CSV 导出、打开位置、排除目录和持久操作记录。

- 按“可重新生成 / 未提交内容 / 未知文件 / 仍被引用 / 受保护”分类。`bin/obj` 要有 .NET 项目清单；`node_modules` 要有 package.json 和锁文件；`.next/dist` 要有已支持的实际构建命令；Cargo/Maven/Gradle 输出要有对应清单。还要求 Git 干净、目录被忽略、没有已跟踪文件、读取完整且任务引用可确认。`.vs`、未知 `dist` 和没有 Git 可恢复性证明的项目只分析；锁文件不能证明依赖源永久可用或依赖没有本地修改，执行前仍需确认。
- 显示逻辑大小、磁盘实际分配、文件数、项目/Git 状态和该项最近修改时间。硬链接在单项内按文件身份去重；理论回收量扣除目录外仍保留的硬链接。工作树和构建子目录有重叠，不能相加。最近修改是该项及子内容的最大修改时间，不冒充 Git 提交日期或项目源代码最后修改日期。
- Git 主/关联工作树、合并目标、锁定、脏状态和失效记录分析。默认合并目标为 origin/HEAD 或本地 main/master，不自动联网 fetch。只有已合并、干净、无忽略文件、无子模块、非主/锁定/托管工作树且没有活动任务引用时，允许 **通过 Git 正常移除 checkout**：不用 `--force`、不删分支、不手工删目录。此操作不进回收站，已提交文件可用保留的分支重新检出；忽略构建产物应先单独处理。失效工作树仅报告，不自动 prune。参考 [Git 工作树说明](https://git-scm.com/docs/git-worktree)。
- 跨工作树构建文件按同一 Git 公共仓库、相同长度和完整 SHA-256 比对，显示相同内容提示，不凭同名/同大小删除。最多 5,000 个大小组、10,000 次哈希、2 GiB 读取；达到上限明确提示，暂未为此比对单独建立持久哈希缓存。
- Codex 任务索引只读打开：优先最高版本 `state_*.sqlite`，检查已支持字段，读取任务编号、cwd、归档/固定状态、rollout 位置和工作树附件；不读取认证信息，不修改 Codex 状态。按路径中的确切任务编号匹配归属，扫描未归档/固定任务的引用记录，仅保留“候选路径是否命中”，不保存消息正文。使用单遍多模式匹配，引用记录不随候选数重复全量读取；索引/记录缺失、格式不支持、变化或超过限制时，相应清理关闭。**未归档不表示正在运行；已归档不表示产物无用；索引无记录不表示任务已失效。**
- Codex 图片、可视化、临时目录、缓存和旧文本日志分析；补丁、日志和归属不明的产物不自动清理。明确属于已归档任务、无活动引用且已读完整的图片/可视化，可以通过“人工确认归档成果回收”：必须输入“我已备份”并再次确认；执行时重新检查归档、引用、Git 和排除规则。生成成果不保证能重新生成，回收后旧任务预览可能失效。Codex 托管工作树只能在 Codex 内归档以保留其恢复关系，此 EXE 不伪造托管归档。认证、配置、SQLite 状态、sessions、archived_sessions、技能和记忆不纳入这个中心的清理。
- NuGet、npm、pnpm、Yarn、pip、Cargo、Gradle、Maven 的常见默认用户目录。HTTP/下载类缓存与源码/私人包/共享 store 分开：NuGet 全局包、Maven 本地仓库、Cargo 源码/Git、Gradle 缓存、pnpm store 保守归为未知，仅分析。自定义环境变量/配置中的缓存目录暂不自动解析，包管理器不随 EXE 捆绑。
- Docker 当前 builder 的构建缓存只读分析，显示 reclaimable/shared 和项目绝对路径线索；有 buildx history 时进一步显示 context/VCS/revision 项目来源。缓存大小是 BuildKit 报告值，不冒充卷实际分配；共享缓存与构建记录没有可靠的逐条关联时明确标未知，不按项目名称猜测或全局 prune。参考 [Docker 缓存统计](https://docs.docker.com/reference/cli/docker/buildx/du/)、[构建历史来源](https://docs.docker.com/reference/cli/docker/buildx/history/inspect/)。

扫描用 SQLite 保存文件快照，不在内存加载完整文件明细；最多200个项目、50,000个发现目录、12级发现深度和1,000,000个快照条目。结果表按目录/缓存/产物组展示并虚拟化。新页面仍是有界全量扫描，不宣称已经复用空间页的 USN 增量引擎；取消不修改文件，需重新扫描才能执行新计划。跳过重解析点、云占位和未读完整的项目。快照在 `%LOCALAPPDATA%\DiskCleanupAssistant\development-manifest.sqlite`，每次重建当前计划；审计在 `development-operations.sqlite`。

清理前重新读取任务引用、Git 状态、文件身份/大小/修改时间/硬链接和当前保护规则；扫描后增删改、任务重新启用或保护规则变化会跳过。普通目录强制进入 Windows 回收站，不回退永久删除；模拟不改文件。执行意图先持久保存，再记录结果/失败原因。回收站未清空时实际释放为0；Git checkout 移除也不把理论字节当作已测量的卷释放量。

同时修正旧 Codex 建议页：年龄/大小评分只作排查排序，不再授权删除；快速清理的 Codex 临时/缓存规则不再默认勾选。**旧快速清理页仍是人工确认的通用规则，不具备本页完整任务归属检查，处理 Codex/开发目录建议使用本页。**

Windows x64 单 EXE包含新页面与 SQLite，无需安装 .NET。Git 状态/工作树需要电脑上已有 Git；Docker 来源需要已运行的 Docker 和相应 buildx，缺失时显示限制，不影响其他页面。

## 相似媒体中心（v2.2.0）

在“相似媒体”页选择目录，可沿用扫描范围白名单，独立启用图片、视频和声音分析。这里只做只读比较，不会删除、链接替换、改写 EXIF 或自动播放媒体；相似候选不能作为完全重复文件直接清理。

- 图片：独立实现 32×32 灰度 DCT 感知指纹、颜色分布与低纹理防误匹配；比较 90°/180°/270°旋转、镜像以及全图/90%/75%中心区域，识别缩放、压缩与部分边缘水印。严格/标准/宽松三档，宽松档需要更多人工复核。任意角度旋转、严重裁剪、大片/中央水印和大幅编辑不保证识别；GIF 只分析第一帧。
- 两张图片并排缩略预览，显示分辨率、体积、EXIF 拍摄日期、隐私提示与建议；不把预览原图和视频全部加载进内存。最高分辨率附近（95%以上）的候选优先，在体积合理候选中以最早已知 EXIF 拍摄日期、较小体积破平局。没有拍摄日期时明确提示；不根据文件修改时间冒充拍摄时间，也不能证明“原图”或主观画质。参考目录内所有匹配项始终建议保留。
- 视频：通过 Windows Media Foundation 在时长的 10%/30%/50%/70%/90% 取样，比较多帧视觉指纹；至少四帧匹配且时长、颜色、画面变化检查通过才归组。重编码/编码填充更宽容，统一黑边最多每边去除15%。静止、黑屏或缺少画面变化的视频不自动归组，防止公共片头/纯色视频误报。不等于逐帧一致检测；剪辑、调速和不同起点的长截取不保证匹配。
- 音乐：Windows 解码为 PCM，归一采样到 11025 Hz，以 4096 点 FFT 的32段对数频带相邻能量关系建立声音指纹，按时间序列比较，可识别不同文件名、音量及部分有损编码的同一录音。最多分析前120秒，容忍最多10秒前置偏移；至少8秒。静音/过于单调的录音不归组；同曲翻唱、现场版本、变速变调、后半段不同的录音不保证正确识别。建议不等于音质评价，需自行试听确认。
- EXIF：检查常见相机、日期、作者、版权、机身/镜头序列号、备注和 GPS 存在性。至少三个已支持字段一致才显示“EXIF 同字段组”，不等于内容相同。只显示隐私字段是否存在，不展示具体坐标；不覆盖所有 XMP、人脸标签或厂商私有信息，不保证“无隐私”。隐私/EXIF 筛选会自动退出“仅相似组”，可查看未匹配图片。
- 截图、下载、Codex生成图片分别分类/筛选，按路径和名称推断，不证明真实来源。右键打开位置、复制路径；全局搜索与 CSV 导出已接入。组内每项直接与固定锚点比较，不通过 A似B、B似C 自动推断 A似C；组排序优先显示保留建议。
- 独立 SQLite 指纹缓存：算法版本、文件身份、长度、修改时间及首尾各最多64KiB采样签名参与失效检查；未变化文件复用成功指纹，失败文件下次重试。缓存不是删除前完整哈希验证；保存的日期/路径/隐私标志也属于个人信息。SSD图片最多两路，机械/未知介质顺序读取，视频/音频单路解码；有界枚举、图片长边256像素指纹、50,000个媒体上限（明确显示部分结果）。取消后保留已完成结果和缓存，下次重新扫描复用；尚不是媒体专用USN增量索引或百万媒体分页。
- 缓存文件 `%LOCALAPPDATA%\DiskCleanupAssistant\media-fingerprints.sqlite`，可确认后单独清空并压缩，不改变媒体、其他索引、配置或操作日志。跳过重解析点、云占位/离线文件及异常恢复文件，不主动下载云端媒体。

图片使用 Windows WIC，视频/音频使用 Windows 内置解码器；常见 JPEG/PNG、H.264 MP4、MP3/WAV 已做真实解码测试。HEIC/WebP、MKV/WebM、其他编码取决于系统已装解码器；未支持/损坏/无权限的文件逐项提示（最多保留500条）。Windows N 缺少媒体组件时需要系统媒体功能包。**软件不需要、也不捆绑 FFmpeg 或 Czkawka**。参考 [Czkawka 工具说明](https://github.com/qarmin/czkawka/blob/master/instructions/Instruction_Krokiet.md) 的功能组织独立实现。

最新版单文件：[DiskCleanupAssistant.exe](D:/SoftWare/DiskCleanupAssistant.exe)。只分享这一个EXE；运行时缓存/配置在使用者自己的本地应用数据目录生成。

## 重复文件中心（v2.1.0）

- “原件目录保护”可添加参考目录，包含其全部子目录；作为额外扫描范围参与比较，即使不在当前白名单中。原件禁止选择、回收和硬链接替换，也禁止成为硬链接来源；已识别的物理别名受到同样保护。操作时用 NTFS 文件名称枚举再次检查参考目录内的别名，不能检查则拒绝操作。
- 参考目录同步保护快速清理、Codex 建议和空间回收页，不改写用户原有永久排除设置。空间排除管理不能解除参考保护，需到原件页确认解除。保护配置损坏/无法读取时禁用处理，不能静默当作没有原件。
- 五种保留策略：最新、最旧、路径最短、分辨率最高、质量指标最高。受保护的所有副本优先保留；其他组至少留一份。策略只生成当前可见组的选择计划，不自动清理；目录批量选择包含子目录，同样保留一份。隐藏的已选项会继续计入总计划，可“取消全部选择”。
- 按整组筛选跨目录、备份/工作重叠、匹配原件；全局搜索命中任一副本时显示完整组。备份识别依赖 backup/bak/archive/备份等目录名称，仅是提示，不证明文件没有价值。
- 组内最多预览 8 项；图片最长边 256 像素，超过 200 MiB 跳过缩略图，文本只读前 4 KiB。预览关闭文件流，不执行 HTML、脚本或外部程序。
- 分辨率读取 WPF 支持的图片格式；质量指标参考已确认无损格式、像素数、位深，再以最新时间破平局。**完整哈希相同的图片本来具有相同画质和分辨率**，这里不是相似图片或主观画质分析；无法读取或非图片退回时间判断。
- 无论快速还是完整模式，处理前重新读取目标与至少一份未选择保留副本、计算完整 SHA-256、核对大小/时间/文件身份。全组选择、保留副本变更或消失、采样碰撞、重解析点、系统路径、非本地固定卷均拒绝；不能依赖历史缓存来执行删除。
- “替换为硬链接”需两次确认，只支持同一本地 NTFS 固定卷及支持安全换名的 Windows。拒绝额外数据流、加密文件、云占位文件和参考原件。先写持久操作意图、建立恢复链接及新链接，再通过 FileRenameInfoEx 原子换名；失败尝试回滚，不能确认时保留恢复文件与路径。不要把硬链接当独立备份：写入任一路径可影响所有链接，权限和时间共享；另存/替换式写入也可能断开链接。
- 理论待释放按分配占用核算；已有外部硬链接的单项保守显示 0。回收站不立即释放内容空间，已释放显示 0，不自动清空回收站。硬链接成功后检查旧实体无剩余文件名、释放本工具的校验句柄，核算被移除实体的分配占用；另列卷可用空间观测变化，可能受其他程序/文件系统延迟影响，不宣称精确归因于本次操作。
- 每项持久记录成功、跳过/失败、原因、原路径、保留路径、理论/核算释放字节、异常恢复路径；界面读取最近 500 项，可导出 CSV。操作完成后旧扫描标记过期，必须重新扫描才能继续处理。正常关闭会等待进行中的重复操作结束；异常退出可查看准备/中间记录，不自动删除恢复文件。
- 扫描先筛同大小候选，再读取物理占用/身份，硬链接只哈希一份。缓存增加文件身份校验，同名、同时间但换了实体时失效；图片元数据按策略需要读取。重复分析仍使用专用内存候选/结果集合，不宣称已支持百万重复候选恒定内存。

原件规则保存在 `%LOCALAPPDATA%\DiskCleanupAssistant\duplicate-references.json`；逐项记录保存在 `duplicate-actions.sqlite`（SQLite WAL）；不会保存文件内容。日志与 CSV 含路径信息，请谨慎分享。异常 `.diskcleanup-backup-*.tmp` 是旧内容的恢复链接，不应随意清理；成功记录中的历史恢复路径通常已不存在。

异常恢复命名空间 `.diskcleanup-*` 同样受到其他清理页面的保护，空间目录整体回收遇到这些子项也会拒绝，避免恢复副本被另一页清理。

参考 [Czkawka 的参考目录说明](https://github.com/qarmin/czkawka/blob/master/instructions/FAQ.md) 独立实现，不捆绑/复制 Czkawka。发布 EXE：`D:\SoftWare\DiskCleanupAssistant.exe`，只分享这个 EXE 即可；运行时配置和日志会写入使用者自己的本地应用数据目录。

## 扫描引擎 2.0（空间分析页）

- 自动识别寻道介质：SSD 最多 4 路受控并行；机械硬盘、未知或混合介质保守顺序扫描，也可手动指定。
- 枚举与元数据读取使用有界流水线，索引单写者分批提交；各阶段共用磁盘读取额度，避免机械硬盘被多个阶段同时随机读取。可选同大小候选 SHA-256 指纹阶段，默认关闭，不作为自动删除依据。
- SQLite WAL 持久化完整文件索引、目录工作队列、元数据、指纹及增长基线。普通第二次扫描仍需枚举名字，但只重新读取新增/修改/上次失败的占用元数据，未变文件只更新核对标记；消失的项目事务性移除。
- 本地 NTFS 且当前权限允许时，使用 USN Journal 的变化目录进行增量更新；日志轮转、重建、身份不匹配、目录解析失败或变化过多时自动全量核对。只读取现有日志，不创建日志或自动申请管理员权限。扫描前的日志头作为游标，扫描期间/暂停期间的变化不会被游标跳过。
- “暂停”等待正在执行的操作结束，保留检查点并展示只读部分结果；可继续扫描、保存快照或停止。“停止并保留”及正常关闭窗口会保存部分汇总；下次保持相同路径、白名单、排除规则和快速/完整模式，在“快照 / 恢复”选择继续未完成扫描。崩溃后已提交记录和工作队列仍在，正在枚举但未完成的目录会重扫。
- 快照是独立 SQLite 文件，包含完整索引而非文件内容。可直接打开保存快照或当前范围上次结果，不重新访问原文件；历史快照、未完成扫描和读取不完整结果禁止回收操作，需先重新扫描。扫描结果可能包含上次缓存与本次已读记录，部分结果不代表当前完整占用。
- 百万结果分页读取：每页 128 条、每个列表最多缓存 8 页，目录节点缓存 512 个；树图只取有占用的前若干项。文件明细搜索/排序在数据库执行；CSV 在后台流式导出完整文件和目录，不创建全量结果集合。任意子串或完整路径搜索仍有数据库扫描成本。
- 单 EXE 内含 .NET、SQLite 原生组件及许可文本；“快照 / 恢复 → 第三方组件许可”可阅读。首次运行会由 .NET 在用户临时目录解压原生组件，不需要另行安装 SQLite。

工作索引位于 `%LOCALAPPDATA%\DiskCleanupAssistant\space\indices-v2`，不同范围/排除/模式使用独立索引，占用本机磁盘；旧版目录 JSON 基线不会删除，但新引擎首次扫描重新建立 SQLite 基线。快照可能暴露路径与文件名，请谨慎分享。

设计借鉴 [gdu](https://github.com/dundee/gdu) 的受控扫描、存储后重新载入思路；独立实现，不捆绑 gdu 或复制其源码。其他快速清理、Codex 建议、重复文件页面仍使用各自专用扫描器，本次持久化引擎升级应用于空间分析。

## 第一阶段功能

- Codex 临时文件、缓存、可视化、图片、会话和项目工作副本扫描。
- Windows 用户临时文件、崩溃转储、错误报告、着色器及缩略图缓存扫描。
- NuGet、pip、npm 和 Yarn 可再生缓存扫描。
- 可选择一个开发项目，查找 `.vs`、`bin`、`obj`、`TestResults`、`dist`、`.next`、Python 缓存和 `node_modules`。
- 按类别查看每一个候选文件的完整路径、大小和修改时间。
- 永久排除指定文件或目录（包含子项），后续清理继续保护；空间分析页可管理排除项。
- 使用精确清理计划；文件在扫描后发生变化时自动跳过。
- 清理历史以本地 JSON Lines 文件记录。
- 分析任意磁盘或多个白名单目录，建立完整、可展开的目录树（保留小文件与空目录）。
- 可点击下钻的矩形树图：按扩展名稳定着色，支持按逻辑大小或磁盘占用决定色块面积。
- 目录树、目录明细与大文件分析显示逻辑大小、实际占用、文件数；提供返回、上级和总览导航。
- 右键打开位置、永久排除、只重扫指定目录、确认后移入 Windows 回收站；新增内容或变化会阻止清理。
- 自动保存目录增长基线，下次同范围、同模式扫描显示增长量、日均增长速率及对比时间；新目录也能被识别。
- 分别显示文件逻辑大小与实际磁盘分配空间，识别 NTFS 压缩、稀疏文件和硬链接。
- 三级重复文件分析：大小分组、首尾分段哈希、完整 SHA-256；硬链接不计为重复副本。
- 重复文件逐项人工选择、每组至少保留一个副本，删除时移入回收站并重新校验。
- Codex 智能建议新增“重复组保留最新”辅助操作：可一键按组勾选可删副本，并在删除前自动保留每组至少 1 个文件，减少误删。
- Codex 智能建议新增一键选择动作：
  - 只选“可重建目录” (`.tmp`、`cache`、`generated_images`、`visualizations`、`archived_sessions`)；
  - 只选“超高优先(80+)”候选，适合先清理大头。
- Docker 引擎占用与可回收空间检测，支持不删除卷的官方安全清理。
- Docker / WSL VHDX 的逻辑大小与宿主机实际占用检测。
- 扫描和空间分析支持取消。
- 全局 `模拟清理（Dry-Run）`：所有清理动作可在不删除文件的情况下预演。
- 可设置“扫描范围白名单”，仅扫描白名单下的目录（多个目录使用换行或分号分隔）。

## 使用方法

双击：

```text
outputs\DiskCleanupAssistant.exe
```

启动后会自动扫描低风险清理项。开发项目、包缓存、Codex 图片、会话和项目副本默认不勾选，需要人工确认。

“空间分析”默认只读取和统计。左侧展开目录，右侧点击目录标题或目录色块下钻；“目录明细”可查看当前目录的全部文件（包括零字节和硬链接），双击目录进入。大文件阈值只影响“大文件”页，**不会截断目录树**。

矩形树图最多展开 4 层，并将密集小项合并为“其余 N 项”；点击合并块可查看完整明细。这只限制绘制数量，完整索引不截断。快速模式的占用是逻辑大小近似值，精确占用请取消“快速模式”后重新扫描。NTFS 硬链接的共享占用稳定归属扫描范围内按路径排序的第一个名称，各目录实际占用之和不会重复计算；改变扫描范围可能改变归属，并不代表该名称可独立释放共享空间。

增长排行与本机上一次同扫描根目录、同排除范围、同快速/完整模式的完成扫描比较；首次扫描建立基线。无法完整读取的目录不参与比较，父子目录增长不相加。基线保存在 SQLite 索引中，不记录文件内容。

右键回收站操作需人工确认（整个目录二次确认），并重新校验子项、大小、修改时间、排除项和链接状态。扫描根目录、系统/程序安装/公共应用数据目录受保护，此操作仅支持本地固定磁盘。移入回收站**不会立即释放磁盘空间**，需要自行清空回收站；软件不自动清空回收站。

“只重新扫描此目录”会把当前分析视图切换到该目录，不重新扫描整个磁盘；主扫描输入和白名单保持不变，“开始分析”可重新分析原范围。CSV 导出使用后台流式读取，包含完整目录与文件索引。

交互参考 [WinDirStat](https://github.com/windirstat/windirstat) 的公开功能介绍；本项目独立实现 WPF 目录索引和矩形布局，未复制其源码或捆绑其程序。

“重复文件”页默认不选择任何文件。程序只把内容完整哈希相同、且不是同一硬链接实体的文件归为一组。

“Docker / WSL”页不会直接修改 WSL 的 Linux 文件系统。Docker 安全清理不使用 `--volumes`，不会删除卷。

## 安全边界

- 不跟随符号链接、目录联接点或其他重解析点。
- 所有清理范围都来自明确规则，不接受任意通配删除命令。
- 执行前再次验证候选文件的路径、长度和修改时间。
- 默认只勾选可重新生成的低风险内容。
- 开发目录、依赖、会话、图片和工作副本均需手动勾选。
- 不直接处理 WinSxS、Windows Update 组件、注册表或 Prefetch。
- 正在使用、权限不足或扫描后变化的文件会被跳过并写入清理结果。

## 测试

测试在随机隔离目录中运行，不会扫描或删除真实用户文件：

```powershell
$dotnet = Join-Path $env:LOCALAPPDATA 'Codex\dotnet-sdk-10\dotnet.exe'
& $dotnet run --project tests\ChatGPTCleanupTool.TestHarness\ChatGPTCleanupTool.TestHarness.csproj -c Release -r win-x64
```

增加 `-- --million` 验证百万条 SQLite 索引、WPF 分页、筛选/排序和有界内存；增加 `--test-recycle` 验证独立临时文件和目录确实进入 Windows 回收站。USN 逻辑通过可注入日志测试，无管理员权限时会报告本机真实读取不可用，不冒称真实卷增量已经测试。

`-- --media-only` 单独验证相似媒体。若设置环境变量 `MEDIA_TEST_FFMPEG` 为测试工具路径，或 `outputs/media-test-tools/decoder` 下有测试用 FFmpeg，则额外生成真实 MP4 和 MP3 重编码夹具，验证多时间点和跨编码；未配置会显式 SKIP，不冒称已测。FFmpeg仅用于测试造数据，不能把此测试目录当发行包。完整回归使用 `-- --million --test-recycle`。媒体测试不上传、不扫描真实用户媒体；界面预览来自隔离夹具。
